# ТЗ для Ульяны: Synapse Campus Browser

**Статус:** проектирование и PoC  
**Заказчик:** команда Synapse / ВСГУТУ  
**Целевой первый релиз:** Windows 10/11, пилот ВСГУТУ  
**Владелец продукта:** Ярослав  
**Технический контур:** Влад — архитектурный review, Ульяна — реализация браузерного контура, Арина — визуальная система и UX-review.

## 1. Зачем делаем

Synapse Campus Browser — не «ещё один Chrome», а быстрый приватный браузер для учебной
среды. Он даёт студенту и преподавателю привычные вкладки, историю, загрузки и настройки,
а также нативно открывает GradeBookAI, расписание и локального ИИ-помощника «Вектор».

Первый пилот работает для ВСГУТУ. Архитектура не должна зашивать название, домены,
расписание, брендинг или правила одной организации: вуз — это подписанный профиль
организации, который можно заменить без пересборки приложения.

## 2. Честная граница продукта

На Windows Tauri использует **WebView2**, то есть системный Chromium. Поэтому нельзя
обещать, что произвольные сайты будут потреблять «в разы меньше Chrome» только из-за
смены оболочки. WebView2 тоже имеет browser/GPU/renderer-процессы, а тяжёлый сайт сам
определяет заметную часть расхода памяти.

Цель продукта измерима иначе:

- один общий WebView2 environment и один профиль на пользователя;
- вкладки не создают постоянно живые окна: неактивные выгружаются в снимок состояния;
- для первой версии одновременно активно рендерятся не более двух вкладок;
- никаких расширений, фоновых сервисов, рекламной телеметрии и предзагрузки чужих сайтов;
- тяжёлые функции (ИИ, просмотр документов, расписание) запускаются по действию человека;
- каждое заявление о памяти подтверждается замером на одном стенде против Edge и Chrome.

Если требуется полный браузерный движок с расширениями Chrome, DevTools-совместимостью и
всеми сложными политиками сайтов, Tauri не подходит: понадобится Chromium/CEF и выигрыш в
RAM исчезнет. Для кампусного браузера Tauri v2 + WebView2 — рекомендуемый баланс размера,
безопасности и скорости поставки.

## 3. Рекомендуемый стек

| Слой | Решение | Причина |
|---|---|---|
| Оболочка Windows | Tauri v2, Rust stable, WRY/TAO | маленький нативный слой и системный WebView2 без второго Chromium в инсталляторе |
| Рендеринг сайтов | один shared WebView2 environment; управляемые WebView/вкладки | уменьшает повторный старт и даёт контролируемый жизненный цикл |
| UI браузера | Vue 3 + TypeScript + Pinia + Tailwind из GradeBookAI | скорость команды и общий дизайн; переносить только независимые компоненты |
| Rust-ядро | `tauri`, `serde`, `tokio`, `reqwest` с certificate validation, `rusqlite`/SQLCipher | команды, профиль, офлайн-данные и правила безопасности вне JS |
| Хранилище | SQLCipher, ключ через Windows DPAPI; отдельные профили | история и настройки не читаются из файлового профиля |
| Блокировка угроз | локальный подписанный список доменов/URL + локальные правила контента | URL пользователя не отправляется стороннему reputation-сервису |
| Обновления | подписанные пакеты с собственным корпоративным каналом | обновление нельзя подменить; отключаемая администратором политика |
| Тесты | Rust unit/integration, Vitest, Playwright, Windows Performance Recorder | функции и реальные RAM/CPU/старт измеряются раздельно |

**Не использовать:** Electron, Chromium/CEF как движок первой версии, облачный Safe Browsing,
сторонние аналитики, удалённые шрифты, CDN без явной необходимости, автозапуск LLM.

## 4. Обязательные сценарии MVP

1. Пользователь открывает приложение и видит новую вкладку: адресная строка, вкладки,
   кнопки назад/вперёд/обновить/домой, быстрые ссылки «Журнал», «Расписание», «Вектор».
2. Ввод адреса или поискового запроса. Адрес открывается, запрос идёт только к выбранному
   пользователем поисковику; по умолчанию поиск отключён до явного выбора.
3. Вкладки: новая, закрыть, восстановить последнюю закрытую, переключить, закрепить,
   дублировать, закрыть остальные. Неактивная вкладка сохраняет URL, title, scroll position
   и снимок, но не продолжает исполнять страницу без специального исключения.
4. История, избранное, загрузки, масштаб страницы, поиск по странице, режим чтения.
5. Настройки: стартовая страница, поисковик, внешний вид, язык, приватность, загрузки,
   HTTPS-only, исключения, очистка данных, доступность, обновления.
6. GradeBookAI открывается как доверенное внутреннее приложение в отдельном строгом
   capability-контуре; его компоненты не получают доступ к истории внешних сайтов.
7. Расписание доступно офлайн из последнего подписанного/проверенного снимка и явно
   показывает дату обновления.
8. «Вектор» не читает DOM чужих сайтов, историю и буфер обмена. Он получает только текст,
   который человек явно отправил, и действует по отдельной политике GradeBookAI.

## 5. Приватность и безопасность — инварианты

- Никакой аналитики, рекламы, crash-reporting третьим лицам, remote fonts или скрытых
  сетевых запросов. Каждое разрешённое внешнее соединение документируется и тестируется.
- Не называть продукт «анонимным»: сайт всё равно видит IP, fingerprint движка и собственные
  cookies. Корректная формулировка — **privacy-first, без телеметрии Synapse и без передачи
  истории сторонним службам**.
- По умолчанию блокировать third-party cookies, трекеры и известные вредоносные домены.
  Исключение — явное, отображается человеку и может быть отозвано.
- HTTPS-only: любой `http://` сначала повышается до HTTPS. Если HTTPS недоступен — блокирующая
  страница с риском и одноразовым/постоянным исключением. Не делать тихий downgrade.
- Навигация через allow/deny pipeline Rust: нормализация URL → HTTPS upgrade → локальный
  blocklist → политика организации → переход. JS не является точкой принятия решения.
- Внешние вкладки не получают Tauri IPC/capabilities. Команды Rust allowlist-ятся по origin
  и окну; привилегированные команды для GradeBookAI не доступны произвольному сайту.
- Профили раздельны. Выход очищает сессию GradeBookAI, кэш встроенных страниц, токены и
  временные данные текущего пользователя; история браузера очищается отдельной понятной
  командой с выбором диапазона.
- Хранилище шифруется SQLCipher, ключ защищает DPAPI. Логи не содержат URL с query-параметрами,
  токенов, ФИО или содержимого страниц.
- Обновления, конфигурация вуза и blocklist подписываются. При неверной подписи сохраняется
  предыдущая проверенная версия и показывается причина.

## 6. Производительность: метрики, а не обещания

### Стенд

Один и тот же Windows 11 ПК, 16 GB RAM, WebView2 одной версии, чистый профиль, три повтора.
Замерять через Windows Performance Recorder/Analyzer и Process Explorer. Указать версии ОС,
движков, сценарий, median и p95. Сравнение вести с Edge и Chrome на тех же URL и условиях.

### Цели MVP

| Сценарий | Цель Synapse Campus Browser | Условие |
|---|---:|---|
| Холодный запуск до интерактивной новой вкладки | p95 ≤ 1.5 с | SSD, чистый профиль |
| Добавочная память оболочки без открытой страницы | ≤ 120 MB private working set | измеряется вместе со всеми дочерними WebView2-процессами |
| Переключение уже выгруженной вкладки | ≤ 250 мс до снимка / ≤ 1.5 с до восстановления | URL и scroll state сохранены |
| CPU в простое | медиана ≤ 1% | 5 минут, одна статичная вкладка |
| Сеть в простое | 0 внешних запросов | кроме явно инициированного обновления |

Цели сравнения с Chrome/Firefox — **отчётные**, а не зашитые обещания: публикуется разница
на конкретных сценариях. Нельзя «побеждать» выключением безопасности, кэша или рендеринга.

### Технические правила экономии

- Одна среда движка; не создавать webview для превью, настроек и каждой вкладки одновременно.
- Freeze/discard фоновые вкладки, ограничить таймеры и анимации в chrome UI.
- Не хранить полный DOM или скриншоты высокого разрешения для всех вкладок.
- Бандл UI дробить; новая вкладка, настройки и GradeBookAI грузятся по маршруту.
- Не добавлять polling; обновления и расписание используют backoff и явный срок свежести.
- Профилировать каждую регрессию: baseline до merge, budget после merge.

## 7. Интеграция GradeBookAI

Переносится дизайн-токены, система локализации `ru/en/zh`, доступность, HeaderBar/иконки и
часть независимых Vue-компонентов. Не копируются в браузер серверные права, JWT-логика,
локальная БД GradeBookAI или бизнес-правила журнала.

| Модуль | Разрешено | Запрещено |
|---|---|---|
| Расписание | читать отдельный публичный/авторизованный контракт, офлайн-снимок | читать базу GradeBookAI напрямую |
| Вектор | открыть выделенную панель и явно передать выбранный пользователем контекст | сканировать историю, DOM сайта, пароли, файлы без выбора |
| Журнал | доверенный origin + отдельная capability-политика | давать внешнему origin IPC/токены журнала |
| UI | палитра, компоненты, a11y, i18n | копировать без владельца и тестов скрытую логику |

## 8. План работы Ульяны

### Этап A — дизайн-документ и каркас, 3 рабочих дня

- Создать новый репозиторий/папку `synapse-campus-browser`, не смешивать с GradeBookAI.
- Зафиксировать threat model, URL pipeline, модель вкладок, модель профиля и capability matrix.
- Поднять Tauri v2 + Rust + Vue/TypeScript/Tailwind, CI с formatter/lint/test/build.
- Реализовать только пустое окно, тёмную/светлую тему Synapse и статичную новую вкладку.

### Этап B — безопасная навигация, 5 рабочих дней

- URL/parser, history, вкладки, back/forward/reload, адресная строка, error pages.
- HTTPS-only, блокирующая страница, локальный test blocklist, исключения.
- Строгое разделение внутреннего и внешнего origin, тесты на невозможность IPC у внешней страницы.

### Этап C — приватность и память, 5 рабочих дней

- Профиль SQLCipher/DPAPI, очистка данных, downloads, cookie policy, блокировка трекеров.
- Discard/freeze неактивных вкладок, диагностический экран потребления памяти.
- Автоматизированный benchmark и отчёт против Edge/Chrome.

### Этап D — учебные модули, 5 рабочих дней

- Новая вкладка с карточками расписания, GradeBookAI и Вектора.
- Только mock contracts; интеграцию с боевыми ПДн после review Ярослава и Влада.
- UX-review с Ариной, keyboard-only и 200% zoom проход.

## 10. Критерии приёмки

- Нет сетевого обращения при простое, которое не описано в allowlist и не показано в capture.
- Внешняя страница не может вызвать Tauri command, прочитать токены GradeBookAI или получить
  историю браузера.
- `http` не открывается молча, известный тестовый вредоносный адрес блокируется, исключение
  прозрачно и обратимо.
- Вкладки, история, downloads и настройки доступны с клавиатуры, понятны на русском и
  не ломаются при 200% масштабе.
- Benchmark соответствует методике, сохраняет процесс-дерево и не скрывает WebView2-процессы.
- Ни одного ключа, токена, реального ФИО или боевой БД в репозитории, скриншотах и логах.
- Перед подключением GradeBookAI выполнен security review Ярослава/Влада и UX-review Арины.

## 11. Открытые решения до старта боевой разработки

1. Кто владелец и где живёт подписанный update/blocklist endpoint ВСГУТУ.
2. Какой поисковик разрешён политикой вуза и как явно объясняется передача запроса ему.
3. Нужны ли гостевой режим, несколько профилей и синхронизация между устройствами.
4. Подтверждена ли правовая модель для Вектора и расписания на инфраструктуре вуза.
5. Нужен ли Android: Tauri mobile использует системный Android WebView, поэтому его надо
   оценивать отдельным battery/RAM/security планом, а не считать бесплатным продолжением Windows.

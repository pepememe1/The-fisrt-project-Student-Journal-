 2. SAST / ПРОВЕРКА ЗАВИСИМОСТЕЙ / SBOM                             [СДЕЛАНО]
--------------------------------------------------------------------------------
 [x] 2.1 SAST — bandit, гейт на MEDIUM и выше. Все 17 находок этого уровня
         разобраны ПОИМЁННО:
         • 🔥 доверие к ключу SSH-хоста было РАЗОВЫМ: комментарий обещал
           поведение `StrictHostKeyChecking=accept-new`, а код его не давал —
           принятый ключ никуда не сохранялся, и каждое подключение по паролю
           оказывалось «первым знакомством». Настоящая находка, починена;
         • SHA-1 в двух местах заменён на SHA-256 (криптостойкость там не
           нужна, но объяснять это каждому анализатору дороже, чем взять
           сильный хеш);
         • остальные помечены `# nosec` С ПРИЧИНОЙ рядом со строкой.
         Обратный ход проверен: внесённая дыра роняет гейт, exit 1.
 [x] 2.2 pip-audit + npm audit. НЕ блокируют сборку осознанно: свежая CVE в
         чужом пакете не должна останавливать выкладку исправления в журнале.
 [x] 2.3 SBOM — CycloneDX, tools/make_sbom.sh, воспроизводимый вывод.
         Замер: 16 + 18 + 291 компонент. Плюс человекочитаемая записка — на
         приёмке спросит человек, а не машина.
 [x] 2.4 gitleaks по дереву И по истории (репозиторий уже переписывали
         filter-branch, уверенности в истории не было — только надежда).
 [x] 2.5 МЕХАНИЗМ ЗАМКА СДЕЛАН 04.09.2026 — tools/freeze_requirements.py.
         Снимает точные версии текущего окружения в server/requirements.lock.txt;
         deploy/install.sh ставит ПО ЗАМКУ, если файл есть, и только иначе — по
         requirements.txt. Роли двух файлов разведены намеренно: requirements.txt
         остаётся объявлением НАМЕРЕНИЯ («fastapi не ниже 0.110»), замок —
         фиксацией ФАКТА. Слить их значило бы либо запретить обновления, либо
         потерять воспроизводимость.
         🔥 Скрипт ОТКАЗЫВАЕТСЯ снимать замок не на Linux, и это не придирка:
         часть пакетов объявлена только для него (sqlcipher3-binary — шифрование
         файла базы). Снимок с Windows их не содержит ПО ПОСТРОЕНИЮ, выглядит
         полным, ставится без единой ошибки — и оставляет боевую машину без
         шифрования ПДн. Отказ громкий, потому что иначе это заметят на проверке.
         Он же отказывается снимать НЕПОЛНЫЙ замок (объявлено, но не установлено):
         замок с дырой хуже отсутствующего, он выглядит как гарантия.
 [!] 2.5а САМ ФАЙЛ ЗАМКА НЕ СНЯТ — его снимают на боевой машине после зелёного
         прогона, одной командой: `python tools/freeze_requirements.py --write`.
         Снять его с машины разработки нельзя (см. выше), и подделывать смысла
         нет: ценность замка не в числах, а в том, что зафиксирована ПРОВЕРЕННАЯ
         комбинация.

 5. MFA ДЛЯ АДМИНИСТРАТОРА                                          [СДЕЛАНО]

 [x] 5.1 TOTP (RFC 6238), server/app/totp.py, чистый stdlib — сорок строк

 [x] 5.2 Коды восстановления: 10 штук, показываются ОДИН раз, в базе только
         хеши (PBKDF2), гасятся по одному.
 [x] 5.3 Обязателен для admin на боевом сервере. Одна точка — require_admin,
         через неё идёт весь административный доступ. Ручки /auth/mfa/* идут
         мимо неё намеренно: иначе замок без двери.
 [x] 5.4 Ограничитель попыток — ТОТ ЖЕ throttle, что у пароля (второй счётчик
         означал бы, что код можно перебирать, не задевая счётчик пароля).
 [x] 5.5 Каждое событие в журнал аудита; аварийный сброс — server/mfa_admin.py,
         только с самой машины, с обязательными --by и --reason.
 [x] 5.6 Секрет НЕ синхронизируется на десктопы (таблица вне SYNC_MODELS).
         Цена названа честно: офлайновый вход админа в программе остаётся
         однофакторным, вторым фактором там служит одобренная машина.
 [x] 5.7 Интерфейс: второй шаг на экране входа + карточка настройки в профиле.
         QR-кода нет намеренно — рисовать его пришлось бы либо лишней
         библиотекой, либо внешним сервисом, а второе означает отправку
         секрета второго фактора чужому серверу.

 🔥 ПОБОЧНАЯ НАХОДКА, ВАЖНЕЕ САМОГО MFA:
    `get_current_user` НЕ ПРОВЕРЯЛ ТИП ТОКЕНА ВООБЩЕ. Подпись у всех наших
    токенов общая, поэтому пропуском работал ЛЮБОЙ выданный нами токен —

    целиком. Нашёл собственный тест, написанный до реализации.
